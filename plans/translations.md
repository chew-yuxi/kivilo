# Translations: Chinese (Singapore/Malaysia) and Thai

Asked by Yuxi on 2026-10-23. The app was English only; nothing was localized.

## Scope, in order

1. **Flutter app** (this branch). Landlords and tenants live in the app, so it is where
   a second language reaches the most people. Ships as a Shorebird patch: the new
   dependencies (`flutter_localizations`, `intl`) are Dart only.
2. Web app and emails. Later, and separately.
3. **Not translated: the report itself.** The PDF, the shared report and every line in
   it stay as written. They are what both parties sign and what the fingerprint covers,
   and the inventory is the inspector's own words. Room template rows come from the
   server (`src/lib/room-templates.ts`) and become report content, so they stay English.
   Server-supplied text (server error messages, notification bodies) stays English
   until phase 2.

## Languages

- `en`: the source.
- `zh`: Simplified Chinese as written in Singapore and Malaysia: 组屋 (HDB), 公寓
  (condo), 冷气 (aircon), 押金 (deposit), 中介 (agent). Any `zh` locale gets it,
  Traditional included, since that reads better than English for most.
- `th`: Thai.

Both are drafts written by Claude and need a native speaker's review before promotion
to stable, the legal wording (deposit, damage, fair wear, signing) first.

## How it works

- ARB files in `mobile/lib/l10n/`, generated by `flutter gen-l10n` into the same folder
  and committed, so a patch build compiles exactly what was reviewed.
- One accessor, `t` (`lib/l10n/l10n.dart`), readable without a `BuildContext`, because
  much of the text is made outside widgets: `ApiFailure`, model status labels,
  notifications. Material's own strings come from `MaterialApp`'s delegates as usual.
- Language is a phone setting in Account: Phone language, English, 中文, ไทย. Kept in
  a file in the app support directory, read before the first frame. Changing it rebuilds
  every element under the app, keeping navigation and drafts.
- "Phone language" reads the platform's preferred locales, which iOS passes through
  without `CFBundleLocalizations` (checked on the simulator). Declaring it in `Info.plist`
  would only add the per-app language list in iOS Settings; that is native and waits
  for the store freeze to lift.
- Dates go through `intl`'s `DateFormat` in the chosen language.

## Status (2026-10-23)

Phase 1 is built on branch `claude/translations`: 1,192 app strings in all three
languages, the setting in Account, localized dates, and `test/l10n_test.dart`. Checked
on the iOS simulator in Chinese and Thai: with the phone set to either language the app
opens in it, so iOS passes the phone's language through without `CFBundleLocalizations`.
Not shipped. Before a patch: a native speaker reviews both ARB files, and the branch is
merged after the supporting-documents work in the main checkout lands (it touches the
same screens).

## Review (2026-10-23)

Every string was read in all three languages. Fixed: Chinese "活跃" (active) reworded
for properties, work and members, the shared-cost sentence, unit number, OK button, and
confirmation titles phrased as questions; Thai now uses ที่พัก for a property, so it no
longer collides with รายการทรัพย์สิน (the inventory).

Server text the app shows is now translated where the app has the data:
- Repair cost terms are rebuilt from the proposal's fields (`ResponsibilityProposal.terms`),
  in the case history too. The check-out maintenance list reads the new additive
  `costAgreementTerms` from `GET /api/v1/inspections/[id]` and falls back to the English
  `costAgreement` from a server without it.
- Team refusals (`agency_conflict`) carry an English sentence and no code, so
  `api_failure.dart` maps the known sentences; a new one shows as the server wrote it.

Still English, and what each needs:
1. Notifications, in the inbox and as pushes. The server writes their title and body at
   creation. Needs the server to know each person's language (store it on the
   Stakeholder when the app changes it) and to write the rows in that language.
2. Emails: signing requests, signed PDFs, notification emails. Same requirement as 1.
3. The web: the pages a landlord or tenant opens from an email (`/sign`, `/updates`,
   `/handover`, tenancy documents) and the agent PWA.
4. iOS permission prompts (camera, microphone, photos): `InfoPlist.strings`, native, so
   after the store freeze.
5. By design: the report, its PDF, and the room template rows, which become report text.

1 to 3 are one piece of work (phase 2): a language on the account, then server-side
messages for notifications and email, then the web pages.
